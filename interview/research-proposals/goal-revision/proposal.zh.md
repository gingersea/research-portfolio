# 面向可靠子目标更新的 Agent 组件与执行模式研究

Components and Agent Modes for Reliable Subgoal Revision

面试讨论稿｜2026-11-19｜尚未实施实验

## 研究问题与边界

当环境变化使原计划失效时，Agent 应该改什么，又应该保留什么？本研究先做一个小规模诊断实验，观察结构化记忆、简短反思和执行模式怎样影响子目标更新。

本稿将“目标自更新”具体定义为：**用户最终目标固定，Agent 在推理阶段自主调整子目标和计划**，不训练模型，也不允许擅自改变用户意图。最终目标如“在预算内送达两个包裹”；子目标如“先取包裹一，再到 A”；动作则是一次移动或取件。道路封闭可以要求换路线，却不意味着可以取消第二件配送。这里研究的是这种局部调整能力。

具体问题有三个：结构化记忆能否减少原始要求的遗漏？加入一次反思能否改善必要调整，同时避免无效调整？逐步决策与先规划后执行，对这些组件的收益是否不同？

## 为什么值得做，以及已有工作

[ReAct（Yao 等，ICLR 2023）](https://arxiv.org/abs/2210.03629v3)交替使用推理、动作和环境观察，为逐步决策提供基础。[Reflexion（Shinn 等，2023）](https://arxiv.org/abs/2303.11366v4)利用语言反馈与跨试验记忆改进表现，不更新权重；本方案的回合内反思仅受其启发。[Self-Refine（Madaan 等，2023）](https://arxiv.org/abs/2303.17651v2)让同一模型生成、反馈、修订，无须额外训练。[Huang 等（ICLR 2024）](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html)提醒：在所研究的推理任务中，缺乏外部反馈的自我纠错可能无效甚至退步。

更直接的参照是 [AdaPlanBench（Liu 等，COLM 2026）](https://arxiv.org/html/2606.05622v2)：逐步揭示约束，约束追踪的收益未必转化为最终成功。[DynaRev（Zhang 等，2026 年预印本）](https://arxiv.org/html/2610.40133v1)研究用户中途修订任务，提示即时响应不等于最终满足要求；其部分评估依赖不完美的模型裁判。

尤其需要承认，Balyan 与 Sharma 的《Benchmarking the responsiveness of LLM-based agentic systems under controlled mid-task perturbations》（Scientific Reports，2026）已有架构比较及受控扰动设计。[作者仓库](https://github.com/AyushBalyan/Benchmark)明确覆盖 ReAct、Reflexion、Plan-and-Execute 与目标漂移、恢复评估。因此不主张首次研究或新基准；本方案的价值是用可判定的小环境，拆开组件与模式，区分“确需更新”和“仍可照原计划执行”。

已有阅读给出的共同启发是：思考更多未必更好，记忆内容是否忠实、反馈是否可核验更关键。本实验据此关注目标保留与实际结果，而不凭反思文字是否流畅判断有效。

## 一个可以先跑起来的实验

设计纯文本 Python 快递模拟器：六个地点、两个包裹、目的地 A/B、已知道路费用。工具只有 move、pickup、deliver、status，环境按确定规则检查动作。所有条件保持相同配送要求与费用预算。

每个基础任务准备同一段脚本历史、有效初始计划和当前状态；各组从下一次决策前的同一快照开始。每题有三种变体：无变化；剩余路线上的道路封闭，但存在可行替代；无关道路变化，原计划仍然可行。两种变化均用中性通知，不提示“必须重规划”。离线枚举器确认可解性、变化标签及八步内可完成，答案不提供给 Agent。这样避免不同组在不同进度遭遇事件的混杂，也明确测试的是局部更新。

采用同一个基础模型、单 Agent，做 2×3 六组比较：

| 执行模式 | 原始历史 | 加结构化记忆 | 记忆加一次反思 |
|---|---|---|---|
| R：逐步决策，每次选下一子目标与动作 | R0 | R1 | R2 |
| P：维护剩余多步计划，观察后可重规划 | P0 | P1 | P2 |

结构化记忆包含原始目标 ID、当前事实、待做/完成子目标、证据 ID；由同一模型在已有调用中生成，只保留最新版，不增加真实答案。反思仅在事件点后做一次，问“旧假设仍成立吗？哪些子目标应改？哪些要求必须保留？”，随后正常执行。所有组看到相同原始事实与历史上限；P 组没有额外反馈。各组输出同样简短的目标状态、证据和当前目标审计字段，仅记忆组将摘要重新放入后续上下文。

统一事件后最多八个动作、十次模型调用、6000 个生成 token；规划与反思都计入，记录实际消耗。参数先在开发集确认后冻结。相同上限不代表实际计算量相同：若反思有收益，下一阶段增加等调用的中性重写对照，再讨论原因。此设计只识别记忆收益和“已有记忆时再加反思”的收益，不能估计完整的记忆×反思交互。

## 怎样判断更新是否可靠

主要指标是最终成功率：环境核验两个原始配送目标全部完成且未超预算。次要指标如下：

- **适当的即时更新**：相关变化后，下一子目标或动作可行，且离线检查表明仍能在剩余预算内完成全部目标，未删除原始目标 ID。
- **不必要更新的损害**：在无变化和无关变化中，改选的下一子目标或动作使全部原始目标无法在剩余预算内完成，或直接丢弃原目标。两种模式都用这一标准；无害的替代路线不算错误。
- **目标漂移**：目标 ID 遗漏、被替换，或声称完成却与环境状态不符。一般执行失败不自动算漂移。
- **恢复延迟与成本**：首次产生有效且保留目标的动作所需步数，以及实际 token、调用数；未恢复单列，不能记作零。

枚举检查只用于离线评分，执行时各组仅获得同样的环境动作反馈。人工抽查至少十条轨迹，检查评分器是否误判；发现错误后修复并重算相关结果。

先用十个开发任务调提示和验证检查器，不计入成绩；再用二十个留出基础任务，每题三变体、六组，共 360 个 episode。以基础任务配对比较成功率差与漂移率差，用二十个基础任务为单位 bootstrap 给出 95% 置信区间，不能把 360 次运行当独立样本。不预先承诺统计功效。多随机种子仅作后续稳定性分析，不增加独立任务数。

## 预期、范围与进度

待检验假设是：记忆可能减少遗漏；反思可能帮助真实变化，也可能破坏稳定情境；执行模式的优劣依赖任务。以上均不是已有实验结果。

暂定四周：第一周完成模拟器和可解性检查；第二周用开发集试跑并冻结协议；第三周跑留出集并抽查；第四周整理六组结果、目标更新轨迹与失败案例。先交付小测试集、条件对比表和错误分类，再决定是否扩展模型或任务。

局限包括单一模型、合成环境、提示和实际计算量的混杂，以及共享前缀只能评估局部更新、不能代表端到端自主能力。已有工作覆盖相似比较，因此这是诊断性试验，不预设论文级创新。目前未构建模拟器、未运行实验，也没有结果数值。

## 面试中的一分钟介绍

我想研究环境变了以后，Agent 如何更新子目标，同时保留用户最初的要求。我会先用一个很小的快递环境：目标始终是预算内送完两个包裹，途中可能封路，也可能出现不影响路线的变化。用同一个模型，比较逐步决策和先规划后执行，再分别加入结构化记忆与一次反思。除了最终成功，我会检查目标有没有丢失、更新是否必要，以及恢复要多少成本。相关架构和扰动比较已有研究，所以我先把它做成诊断实验，检验哪些组件在什么情境下有帮助，再考虑扩大范围。

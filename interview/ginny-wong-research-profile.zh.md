## 1. 核心判断

从本次核验的共同署名论文看，Ginny Wong 参与的研究可以概括为：**研究模型如何表示知识、进行推理、利用多模态证据，以及如何评测这些能力能否支持更复杂的智能行为。**

与这次 Agentic AI 面试联系最直接的三个方向是：

1. **推理与泛化：** 模型如何形成、应用和修正规则，什么条件下显式推理有帮助。
2. **科学探索型 Agent：** 如何通过实验和文献检索获取证据，发现规律或形成可检验的假设。
3. **多模态证据与记忆：** 如何在长上下文和多次交互中找到、保存并正确使用信息。

这是一份基于公开论文的主题综合，不是她本人给出的研究议程，也不能据此确定个人贡献、指导风格或实际面试题。下面把可核验事实与面试准备建议分开。

## 4. 主要研究方向及其联系

### 4.1 逻辑推理、抽象与泛化

**文献依据。** LMPNN 涉及知识图谱上的逻辑查询；AbsInstruct 涉及抽象能力训练；The Curse of CoT 与 LogiDynamics 分别检验不同推理方式的局限和适用条件。具体方法和证据见配套 [读物详解第 2–4、8 章](reading-guide/reading-guide.zh.md)。

**方向理解。** 这里关注的不只是某次答案是否正确，还包括规则来自哪里、是否可迁移、是否能正确执行，以及中间解释是否值得信任。逻辑形式、语言表达和视觉输入可能承载相似任务，却引入不同的困难。

**对 Agent 的意义。** 一个 Agent 可以把用户目标拆成步骤，但步骤看起来合理不代表它能完成任务。需要研究错误来自目标理解、假设形成、规则执行还是反馈使用。

**适合准备的讨论。** 能用同一个案例解释归纳、溯因与演绎；能说明怎样通过标准规则或标准状态对照隔离问题；能解释为什么更多推理文本未必产生更多有效信息。

### 4.2 面向科学探索的 Agent

**文献依据。** NewtonBench 面向实验交互中的规律发现；AgentIdeaBench 面向文献支持下的科研构思。二者把研究活动中的不同环节变成可评测任务，不能直接视为完整自动科学家。[NewtonBench](https://arxiv.org/html/2510.07172v3) · [AgentIdeaBench](https://arxiv.org/html/2609.07611v1)

**方向理解。** 可以区分“读懂已有知识”“提出候选解释”“选择下一次信息获取行动”“用新证据更新假设”。把这些环节串起来之后，还要分析究竟是哪一环带来提升。

**对 Agent 的意义。** 行动不仅为了完成外部目标，也可以为了减少不确定性。例如，一个实验的价值可能在于排除错误假设，而不是立即得到一个更高的任务分数。

**适合准备的讨论。** 实验设计、探索与利用、可辨识性、噪声、符号结构与数值拟合的区别，以及科研构思的新颖性、可行性和可检验性。

**证据边界。** 发表基准或构思评分不等于验证了真实科学发现。对预印本应尤其注意方法与局限，而不是只引用摘要中的积极表述。

### 4.3 多模态长上下文、记忆与证据检索

**文献依据。** MMLongBench 和 MemLens 分别提供长上下文与多模态记忆的评测视角。进一步的 *Can Retrieval Heads See Images?* 研究关注检索相关注意力头，并通过有针对性的屏蔽与随机屏蔽比较考察其功能作用。[MMLongBench](https://arxiv.org/html/2505.10610v3) · [MemLens](https://arxiv.org/html/2605.14906v1) · [检索头论文](https://aclanthology.org/2026.emnlp-main.1264/)

**方向理解。** 这条线既问系统能否完成任务，也开始问哪些内部结构与证据定位有关。检索相关注意力并不等于模型全部推理过程；干预结果也需要限定在被测试的模型和任务中。

**对 Agent 的意义。** 长任务需要保存过去的观察，同时避免遗漏图像细节、使用过期记忆或混淆对象。系统必须能追溯“这个判断来自哪次观察”，而不是只积累自然语言摘要。

**适合准备的讨论。** 感知、检索、记忆和推理的分层诊断；上下文容量与有效利用的区别；视觉信息压缩；时间更新；来源追踪；拒答与可靠性—覆盖率权衡。

### 4.4 常识因果与社会认知：值得了解的延伸

**文献依据。** COLA 研究上下文中的常识因果关系。XToM 建立多语言心智推理评测，涉及模型对他人心理状态的推断，并显示语言理解表现与这类推断能力并不能简单等同。[COLA](https://aclanthology.org/2023.acl-long.288/) · [XToM](https://aclanthology.org/2026.acl-long.805/)

**方向理解。** 对环境的理解既包括事件之间的关系，也可能包括他人知道什么、相信什么或想做什么。任务中的表现应与人类认知能力的强主张区分开；心智推理 benchmark 并不证明模型具有人类意识。

**对 Agent 的可能意义，属于本报告推断。** 在协作任务中，Agent 可能需要区分自己的信息与用户的信息，避免假定双方知道相同事实。多语言条件还要求检验这种能力是否稳定。

**准备优先级。** 先掌握混杂、观察与干预，以及“真实状态与他人相信的状态可能不同”。除非你的提案直接研究协作或多语言，不必把这一分支放在最前面。

## 5. 跨论文可见的方法特点

以下是对所选论文的分析归纳，不是对面试官个人偏好的断言。

### 把宽泛能力拆成可检验任务

“会推理”“有记忆”“能做科研”都太宽泛。准备时应能把一个能力拆成任务、输入条件、可观察输出和失败标准。一个有效的研究问题通常允许你解释什么结果会推翻自己的观点。

### 用对照区分多个可能原因

加入模块后分数提高，可能源于更多计算、更好的数据、更强的基础模型或真正的方法优势。面试中的实验说明应包含相同预算的基线、模块消融、标准中间输入，以及与假设对应的指标。

### 重视证据质量与测量边界

检索到内容、保留原始视觉细节、判断证据是否足够，都是可靠推理的前提。对自动评估器，需要问它与目标构念是否一致，而不是只问它给分是否稳定。

### 把失败当作研究对象

负面结果可以有研究价值，但必须说明失败发生在什么条件、有哪些替代解释，以及后续怎样检验。不能把一个失败案例直接推广成普遍不可能。

## 6. 你的项目与这些方向的匹配

| 现有经历 | 最有依据的连接 | 面试中应准备的证据 | 应避免的扩大表述 |
|---|---|---|---|
| 优化与 LoRA 比较 | 模型适配、实验归因、能力评测 | 实际更新路径、配置控制、负面结果和修正 | 已证明一种普遍优于 LoRA 的优化算法 |
| 视频物理一致性 | 多模态证据、观测有效性、验证与拒答 | 可见性、身份、测量门控、精度与覆盖率 | 已完成可靠世界模型或自主科学发现系统 |

建议用下面这段逻辑连接两项经历：

> 我的两个项目都让我关注实验结论的依据。优化项目需要确认性能变化是否真的来自所研究的更新方法；视频项目需要确认观察是否足以支持物理判断。研究 Agent 时，我希望把这种经验用于区分推理、工具、记忆和额外计算各自的贡献，并明确系统何时需要更多证据。

这是一段建议表达，不新增任何已完成成果。定量结论仍以仓库中的 [证据说明](../EVIDENCE_GUIDE.md) 和两份项目介绍为准。

## 7. 面试讨论优先级与可提的问题

### 建议优先级

| 优先级 | 准备内容 | 应达到的程度 |
|---|---|---|
| 第一层 | 推理类型、CoT 局限、科学探索、实验对照 | 能讲概念、给反例、设计一个可执行实验 |
| 第二层 | SFT/LoRA、长上下文、RAG、记忆与不确定性 | 能解释机制并联系自己的实验 |
| 第三层 | 知识图谱、因果、多语言心智推理、注意力头干预 | 理解问题与局限，遇到追问时能展开 |

强化学习、多 Agent 协作、GPU 计算仍是相关基础，但本次选取的材料不足以将其中任一项确定为她唯一或首要研究方向。不要仅因 NVIDIA 背景就把准备重点完全放到 CUDA 内核，也不要只背框架 API。

### 可用于学术交流的问题

1. 在科学探索 Agent 中，您认为目前最值得先解决的是假设质量、实验选择，还是验证与停止条件？
2. 研究推理方法时，怎样设计一个既能隔离机制、又保留实际任务复杂度的 benchmark？
3. 对多模态记忆，保留原始证据与压缩成本之间，哪些任务最适合建立清晰的权衡指标？
4. 对学生研究项目，您更建议先做一个可信的失效诊断与评测，还是围绕明确瓶颈提出一个小型方法改进？

这些是基于研究主题拟定的交流问题，不是已确认的面试内容。使用时应选择自己能够继续讨论的一两个。

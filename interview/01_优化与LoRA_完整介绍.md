## 一、30 秒概述

我的第一个项目研究大语言模型如何在有限资源下完成适配。我比较了交替优化和 AdamW，也比较了全秩更新和 LoRA，希望分清性能变化究竟来自优化方法，还是来自可训练参数的组织方式。研究过程中，我发现 ALS 闭式更新在部分配置下会造成严重失稳，也通过对照实验发现，原先归因于梯度注入的收益实际上可以由普通 SGD 解释。这个项目让我形成了一个研究习惯：先确认新组件确实生效，再确认它是否比简单基线更好。对于 Agentic AI，这对应的是如何可靠地适配 Agent 的基础模型，并验证更新带来的真实能力收益。

## 二、完整面试口述稿，约 4–5 分钟

我的第一个项目是大语言模型后训练中的优化方法比较，重点是交替优化与 LoRA。我想回答的问题是：在数据和算力有限的情况下，能否用局部的闭式求解，减少模型适配对大量梯度更新的依赖，同时保持训练稳定性和模型能力？

这里需要区分两个概念。AdamW 或 SGD 决定参数怎么更新；LoRA 决定允许哪些参数变化。LoRA 冻结原来的权重，通过两个较小矩阵表示权重增量。因此，“某种优化算法是否优于 LoRA”不能直接作为一个干净的比较，因为它同时改变了优化器和参数形式。

我的实验设计因此采用两条轴：一条是交替优化与 AdamW，另一条是全秩与 LoRA。交替优化方案称为 ASP，包含 ALS 局部最小二乘求解、SGD 更新和扰动三个阶段。ALS 的吸引力在于，当输入特征和目标固定时，可以直接求出一个局部线性问题的解。但是，局部拟合更好，并不保证整个语言模型的预测更好。这正是需要实验验证的地方。

实验以 WikiText-2 语言建模为基础，从 OPT-125M、Qwen2.5-0.5B 等小模型扩展到 Qwen2.5-7B。7B 主对照采用三个随机种子，LoRA 的秩为 8，作用于注意力的 Q、K、V、O 投影。除了语言建模损失，我也检查了下游任务、显存和运行时间。实际实现存在一个重要限制：7B 的全秩交替优化无法稳定完成，而 LoRA 分支移除了不能直接兼容的 ALS 阶段。因此，这一部分应视为有明确缺项和实现差异的对照，不能声称完成了完全干净的四组因果归因。

研究中最有价值的工作，是对失败进行拆解。在保存的 7B 消融记录中，保留 ALS 计算、但恢复权重的分支可以继续训练；真正写入 ALS 权重更新后，记录的损失指标急剧恶化；加入后续 SGD 也没能挽救这个过程。这个结果把问题定位到具体的权重更新路径，而不只是笼统地说“大模型不好训练”。我也讨论过残差传播与失稳的关系，但目前更适合把它作为机制假设，而不是普遍成立的深度定律。

我随后尝试把 ALS 产生的方向作为梯度修正，而不是直接写入权重。这一方案最初看起来能够收敛，但检查训练循环后发现，梯度注入发生在 optimizer.step 之后，下一步又被 zero_grad 清除，所以它没有真正参与参数更新。我补做了同样 4,800 次 SGD 更新的纯 SGD 对照，两条历史记录的最终 PPL 约为 6.82 和 6.83。这些数值使用的是旧评估实现，我只把它们作为诊断线索；更直接的证据是代码中的更新时间顺序。最终没有依据把这项收益归功于新的注入机制。

项目也促使我审查评估本身。我发现早期 OPT 实验存在 tokenizer 不匹配和 padding 标签未屏蔽的问题。修正后，固定学习率的 SGD 在该实验中的 PPL 约为 50.67，余弦衰减约为 54.71，指数衰减约为 57.09。这支持了一个更朴素的解释：部分变体差异来自学习率设置，而不是额外的 ALS 机制。保存的 HellaSwag 评估也显示，在这组小数据适配实验中，LoRA 的三种子平均准确率约为 59.74%，全秩更新约为 56.72%。这提醒我，训练目标上的改善需要与下游能力一起判断。

项目最终的成果是一套可检查的训练与对照框架、失稳诊断、评估纠错和有证据的负结果。目前没有证明新的交替优化方法优于标准基线。它与 Agentic AI 的联系在于：Agent 的专门化、工具使用训练或后续能力更新，同样需要回答“更新是否稳定”“是否保留原有能力”“增加的组件是否真的有效”。我希望把这里形成的对照实验和收益归因能力，进一步用于 Agent 的真实交互任务。

## 三、方法与实验配置，供深入追问

### 1. 核心方法，用简单语言解释

- **全秩更新**：允许原权重矩阵的各个方向发生变化；本项目全秩梯度分支更新模型参数。
- **LoRA**：冻结基础权重，以低秩增量适配模型：`W_eff = W_0 + (alpha/r) BA`。它是一种参数化方法，可以与不同优化器配合。
- **ALS**：固定当前输入特征和目标后，求解带正则项的局部最小二乘问题。例如 `min_W ||XW^T-Y||_F^2 + lambda ||W||_F^2`。闭式解只保证这个局部代理目标的最优性，不能推出整个非线性模型的交叉熵下降。
- **ASP**：项目中的 ALS、SGD、扰动组合流程。具体版本执行哪些阶段，要以对应脚本为准。
- **A-SYNC**：尝试把 ALS 解与原权重之差作为梯度偏置。原实现的注入时序无效，因此不能把其训练结果当作该机制有效的证据。

### 2. 研究设计矩阵

| 参数形式 | AdamW | 交替优化分支 |
|---|---|---|
| 全秩 | Protocol B：梯度更新全参数 | Protocol A：ALS + SGD + 扰动；7B 上失稳 |
| LoRA | Protocol D：AdamW 更新低秩参数 | Protocol C：实际 7B 路径为 SGD + 扰动，移除了 ALS |

这个矩阵有助于提出“优化器因素”和“参数形式因素”的问题。由于 A 失稳、C 的组件不同，7B 结果不能用于完整的二因素交互效应估计。也不能把 C 与 D 的差异直接称为 ALS 的净效应。

### 3. 不同实验轮次的配置

| 实验 | 可核实配置 | 目的与边界 |
|---|---|---|
| 7B 主对照 | Qwen2.5-7B；WikiText-2；训练前 1,600 条、测试前 200 条；最大序列长度 2,048；目标预算 800 步；种子 42/123/456 | 旧评估路径有 padding 标签问题；“800 步”也不能直接等同严格计算预算匹配 |
| LoRA 设置 | r=8，alpha=16，dropout=0.05，Q/K/V/O 投影 | 来自实际 `run_7b_gpu.py`，不套用其他配置文件 |
| 硬件 | 项目记录使用 2×RTX 5090，每卡 32 GB；7B 全秩采用 DeepSpeed ZeRO-2/优化器卸载等配置 | 各分支资源安排有差异，不把全部运行当作完全相同硬件利用率 |
| 7B 纯 SGD 对照 | 96 周期×50 次更新；lr=2e-4；momentum=0；weight decay=0.01；batch=2；长度128；bf16 | 对照原 A-SYNC 的 SGD 更新预算；不是与 800 步主矩阵直接比较；并非严格逐批次配对的多种子证明 |
| 修正后的 OPT 学习率对照 | OPT-125M；模型自身 tokenizer；padding 标签设为 -100；16×50=800 次更新；batch=4；长度128；fp32 | 固定/余弦/指数衰减；这是保留的实验结果，不宣称普遍学习率规律 |
| 下游评估 | HellaSwag 验证集10,042题，0-shot；B、D 各三种子结果 | 衡量一种下游能力；不等同工具调用或 Agent 长程任务成功率 |

评估采用 PPL 时，数值越低表示在该评估协议下平均预测损失越低。不同 tokenizer、padding 处理、文本截断和测试子集的 PPL 不能混用。

## 四、最终成果与可用数字

### 1. 可以作为研究成果讲述的内容

1. 搭建了包含模型加载、参数适配、训练阶段调度、评估、资源记录和结果保存的研究框架。
2. 用有无权重写入的对照，把部分失稳定位到 ALS 更新路径。
3. 发现 A-SYNC 注入时序无效，并用简单基线检查收益归属，撤回“新注入算法带来收敛”的解释。
4. 修正早期 OPT 评估配置，并保留修正前后的记录。
5. 引入下游评估，避免把语言建模指标当作模型综合能力。
6. 形成报告和海报。成果性质是方法比较、诊断与负结果，没有已验证的新优化器性能突破。

### 2. 推荐使用的结果表

| 结果 | 数值 | 面试中的准确解释 |
|---|---:|---|
| 修正后 OPT 固定学习率 SGD | PPL 50.6674 | 当前实验条件下的最终值 |
| 修正后 OPT 余弦衰减 SGD | PPL 54.7131 | 支持学习率调度影响结果 |
| 修正后 OPT 指数衰减 SGD | PPL 57.0898 | 同上，不推成固定学习率普遍最优 |
| 修正后 OPT 低秩探针对照 | 纯SGD 50.6988；r=64/256/1024 为50.7449/50.5843/50.6597 | 没有建立可靠的额外收益；不能仅凭微小差值声称显著改进 |
| 修正后 OPT 软目标对照 | SGD 52.4472；ALS 52.5531 | 此设置下没有显示 ALS 优势 |
| HellaSwag，保存的统一汇总 | 全秩 AdamW约56.72%；AdamW+LoRA约59.74% | 三种子均值，采用 `downstream_eval.json` 的 `acc,none`；优势约3.02个百分点，非已完成显著性检验 |

### 3. 只作历史诊断的数字

7B 旧主矩阵记录 B约1.25、C约135.36、D约10.41；旧 A-SYNC/纯SGD 记录6.8185/6.8341。这些数值存在于结果文件，但配套脚本的 `labels=input_ids.clone()` 没有屏蔽 padding。不能把它们写成经过完整校验的标准 WikiText-2 性能，不能据此计算“能力提升多少倍”。本次没有重跑训练或测量这一缺陷的影响量。

“LoRA 快87倍/1000倍”“ALS 在28层必然失效”“每层恒定放大1.08倍”均不作为介绍结论。原 FLOPs 算法含简化假设，低秩可训练参数减少不等于骨干前向和激活梯度计算按同比例减少；深度和架构也存在混杂。

## 五、如何自然衔接 Agentic AI

**已有工作支持的能力**：模型适配、优化流程实现、消融设计、参数更新审计、下游评估和失败归因。

**合理的研究延伸**：为不同工具或领域训练适配模块，比较更新后成功率与通用能力保持；对“反思模块”“额外规划步骤”“记忆更新”等组件做启用/禁用和预算对齐的对照。

**尚未做过的内容**：在线持续学习、Agent工具调用训练、长程交互任务、强化学习式策略更新。不要把未来延伸说成已经完成的实验。

可直接使用的连接句：

> 这个项目让我关注模型更新的有效性。在 Agent 系统中，我会用同样的方法问：新增加的反思、工具学习或记忆模块，是否真的改变了决策，又是否在控制成本后提高了任务成功率？

## 六、常见追问与回答

**问：你提出的方法最后有没有超过 LoRA？**

答：目前没有足够证据支持这一点。项目的有效成果是比较框架、失稳定位和负结果。尤其是简单基线解释了原先归因于注入机制的收益，这让我更准确地确定了哪些方向值得继续。

**问：为什么局部闭式解反而破坏模型？**

答：闭式解优化的是固定特征下的局部平方损失，模型最终目标是整个网络的语言建模损失。局部目标与全局目标不一致，大幅修改输出分布还可能破坏预训练状态。实验支持具体 ALS 更新路径会触发严重失稳，但还不足以把残差放大解释确认为唯一机制。

**问：你的 2×2 比较是否真的公平？**

答：设计意图是拆开优化器和参数化，但实际7B实现存在C分支移除ALS、A分支失稳等限制，所以我不会声称它是完全无混杂的因果实验。进一步的比较需要对齐数据与更新预算，明确组件差异，同时报告真实时间、显存和可靠的计算量测量。

**问：6.82 和6.83足以证明两个方法完全一样吗？**

答：不能。接近的终点和轨迹只是支持性现象，最直接的证据是注入发生在step之后、下一轮又被清空。也不能把这组旧评估的接近推广到所有正确实现的梯度注入方法。

**问：为什么不直接报告1.25 PPL？**

答：原结果文件确实记录了这个数字，但配套数据处理把padding也放进labels。attention mask并不会自动把这些位置从交叉熵标签中去掉。因此它需要修正评估后重跑，才能作为标准性能主张。

**问：你下一步会怎么设计Agent方向实验？**

答：我会选一个有自动验收条件的工具任务，在相同基础模型和交互预算下比较未适配模型、LoRA适配和其他更新方案。主要终点是未见任务成功率，同时报告工具调用成本和原有能力保持。先验证评估器，再讨论更新算法。这是后续设计，不是这个项目已经完成的实验。

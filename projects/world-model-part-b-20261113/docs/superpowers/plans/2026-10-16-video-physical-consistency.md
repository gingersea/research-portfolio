# VideoWorld-PhysBench: Video-Model Physical-Consistency Benchmark — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local, reproducible, two-part physical-consistency benchmark for open video-generation models (Wan2.1-1.3B first, CogVideoX-5B second) on 2× RTX 5090, producing a codebase, prompt sets, results with a leaderboard, and an English research report.

**Architecture:** Two-stage evaluation. Part A (measurable physics): prompts for free-fall / pendulum / projectile / horizontal-motion scenes → generate videos → extract object trajectories with background subtraction → fit physical parameters (g, T) → score against real physics. Part B (complex scenes): prompts for collisions / fluids / support / multi-object interaction → generate videos → sample frames → Claude-as-VLM-judge scores physical violations via a fixed protocol with a calibration set. Everything runs locally with zero API cost. A CLI tool `physcheck` ties the stages together; results are written as JSONL artifacts that a report script aggregates into tables/leaderboards.

**Tech Stack:** Python 3.12; torch 2.9.0+cu128 (already installed); diffusers (to install); transformers 4.57.6 (installed); numpy, scipy, opencv-python-headless, imageio (installed); pytest for tests. Models via HuggingFace (non-gated, apache-2.0 / other). Time convention: model nominal fps as the physical clock; pixel→meter calibration from known object size stated in the prompt.

**Spec:** `docs/superpowers/specs/2026-10-16-video-physical-consistency-design.md`

## Global Constraints

- Hardware: 2× RTX 5090, 32 GB each, single-GPU jobs only; CPU fallback acceptable for detection/judging. Disk free: 2.4 TB. RAM: 256 GB.
- Zero API spend. No paid VLM calls. Claude-as-judge runs through the local agent's Read tool; judge backend must be swappable via env vars (OPENAI_API_KEY / GEMINI_API_KEY) in code, unused this month.
- Generated-video scale: per model ≤ 100 videos; N = 3 seeds per prompt; total wall-clock ≤ 1 month.
- All code under `benchmark/`; all prompts under `benchmark/prompts/` as JSON files; all results as JSONL artifacts with model + prompt_id + seed + commit hash recorded.
- Part A must output verifiable physical numbers (g in m/s², T in seconds) with errors; detector must pass a synthetic-animation validation gate before production runs.
- Part B judge runs blind to model identity, isolated per video, fixed prompt template + fixed JSON output schema; judge model name + version recorded; all judge inputs/outputs archived; calibration set (known-violation control prompts) must be 100% correctly flagged or the protocol is invalid.
- Repo hygiene: the weather-domain content (old README, proposal*.md, experiment-report*.md, plan/, old pilot spec) is deleted in Task 12; git commits are made throughout, pushed to github.com/gingersea/world-model-physical-consistency.

## Review Focus

1. Videos where the object never appears or vanishes mid-video (generation failure): the detector must report a `detection_failure` instead of returning a garbage g value. → Task 4 test: an all-background synthetic video yields `detection_failure`.
2. Detector on real generated video with compression artifacts / flickering objects: trajectory must not silently produce confident fits; fit quality thresholds must mark `fit_failed`. → Task 4 test: a synthetic video with an object plus flicker noise yields either a correct g within tolerance or `fit_failed`, never a confident wrong g.
3. Judge receiving frames without a video ID / model name: judging must be blind but traceable; the judge harness must refuse (raise) on missing `video_id` in the prompt payload. → Task 8 test: building a judge prompt from a record lacking `video_id` raises ValueError.
4. Calibration set: any calibration video scored as "no violation" must make the protocol invalid with a clear error, not silently pass. → Task 8 test: simulated judge outputs that miss a calibration violation produce an InvalidProtocol error with the offending video ID.
5. FPS/time-scale mismatch: a generated video whose metadata says 16 fps but content is 81 frames must use metadata fps for time conversion; missing metadata must raise rather than guess. → Task 4 test: trajectory-time conversion raises on missing fps metadata.

### Task 5: Physics fitting and the detector validation gate

**Files:**
- Create: `benchmark/physcheck/detect/fit.py`, `benchmark/physcheck/detect/validate.py`
- Test: `tests/test_fit.py`, `tests/test_validate.py`

**Interfaces:**
- Consumes: `tracker.track_object`, `synthetic.render_scene`
- Produces:
  - `fit.fit_trajectory(kind: str, trajectory_px: list[tuple[float, float]], times_s: list[float], pixels_per_meter: float, calib: dict) -> dict` returning `{"status": "ok"|"fit_failed", "reason": str|None, "params": dict, "params_std": dict|None}`. Kinds and param keys:
    - `free_fall` → `{"g": float}` (from `y(t) = y0 + v0 t + ½ g t²`, least squares; g recovered in m/s² after px→m conversion; y-axis down positive, screen coordinates flipped accordingly)
    - `projectile` → `{"g": float, "v0x": float}`
    - `pendulum` → `{"T": float}` (from x(t) sine fit; T in seconds)
    - `horizontal_motion` → `{"v0": float, "decel": float}`
    `fit_failed` triggers when R² < 0.6 or residual RMS in pixels > 3.0 (both thresholds are constants named in the module).
  - `fit.compute_pixels_per_meter(track_result: dict, calib: dict) -> float` — measures the object's pixel diameter from the tracker's component sizes (Task 4 must therefore also return per-frame component area/diameter — see note below) and divides the known `calibration.object_diameter_m`.
  - `validate.validate_detector(cfg: Config) -> dict` returning `{"passed": bool, "results": [{"kind": str, "param": str, "true": float, "estimated": float, "rel_err": float}], "failures": list}`. Gate rule: for each synthetic kind, the estimated g (free_fall, projectile) must be within 10% of 9.8; pendulum T within 10% of `2π√(L/g)`; horizontal v0 within 15% (deceleration only sanity-checked: sign correct, magnitude within 50%). `passed` is True iff every rule holds AND no `detection_failure`/`fit_failed` occurs on clean synthetic videos.

**Files:**
- Create: `benchmark/physcheck/judge/protocol.py`, `benchmark/physcheck/judge/calibration.py`

**Interfaces:**
- Consumes: `frames.sample_frames`
- Produces:
  - `protocol.JUDGE_TEMPLATE: str` — a fixed English prompt: "You are a physics-consistency judge for generated videos. You are shown N annotated frames sampled from a video. Identify physical violations visible in the frames. A violation is an event that contradicts elementary physics (gravity, support, collision/contact, fluid behavior, rigid-body motion). For each violation, report the frame index, the category (one of: `gravity`, `support`, `collision`, `fluid`, `rigid_body`, `other`), a one-sentence description, and your confidence (0–1). Output JSON only, in the schema below. Do not speculate about motion between frames; judge only what is visible in the frames." plus the output schema.
  - `protocol.JUDGE_OUTPUT_SCHEMA: dict` — `{"video_id": str, "violations": [{"frame_idx": int, "category": str, "description": str, "confidence": float}], "judge_model": str, "judge_version": str, "notes": str}`.
  - `protocol.build_judge_payload(record: dict) -> dict` where `record` has `video_id`, `grid_path`, `n_frames`; raises `ValueError` if `video_id` missing; returns `{"prompt": str, "schema": dict, "video_id": str, "grid_path": str}`. Blindness: no model identity anywhere in the payload; `video_id` is an opaque hash-like ID (`partB_{prompt_id}_{seed}`), and the mapping to models lives only in the results manifest, not in judge payloads.
  - `protocol.parse_judge_output(text: str, video_id: str, judge_model: str, judge_version: str) -> dict` — extracts the JSON object (handles ```json fences```), validates against `JUDGE_OUTPUT_SCHEMA` (categories restricted to the enum; confidence in [0,1]; frame_idx in [0, n_frames)), returns the normalized dict or raises `protocol.ProtocolError` with the parse problem.
  - `calibration.check_calibration(judge_outputs: dict[str, dict], calibration_prompts: dict) -> dict` returning `{"valid": bool, "violations": list[str]}` — for each calibration video, valid iff ≥ 1 violation of the expected kind (or `other`) is reported. `valid` False → the whole protocol is invalid; the function raises `calibration.ProtocolInvalid` (or returns valid=False with the offending video IDs — pick one and be consistent) naming the video IDs that failed.

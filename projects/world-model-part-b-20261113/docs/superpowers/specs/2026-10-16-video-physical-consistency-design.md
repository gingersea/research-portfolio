# VideoWorld-PhysBench: 视频生成模型物理一致性评测基准 — 设计文档

## 1. 意图与背景

**要做什么**:一个针对**开源视频生成模型**的物理一致性评测基准(benchmark),包含:

1. 一份可复现的评测代码库(生成 → 检测 → 打分 → leaderboard)
2. 一套评测集(prompt 集 + 物理检测器 + 裁判协议)
3. 一份调研报告(文献综述 + 实验结果),写成未来可扩展成论文的底稿

**交付地点**:`github.com/gingersea/world-model-physical-consistency`(私有仓库,已存在)。仓库内现有气象方向内容(README 调研报告、proposal、experiment-report、pilot-design)全部删除或移出,以视频生成模型方向取代。

**为什么值得做**:现有物理一致性基准(Physics-IQ、VideoPhy-2、PhyGenBench、T2VPhysBench、Principia)主要测**商业闭源模型**(Sora/Runway/Pika/可灵),依赖 API 和专有数据,无法在消费级硬件复现;开源模型的物理一致性缺乏**本地可复现、低成本**的系统评测。这是一个明确的生态位缺口。

**为什么现在**:开源视频生成模型(CogVideoX、Wan 系列)质量已接近可用;这些模型将是大量下游研究的基础,其物理一致性的系统测量对社区有用且成本极低(本研究只需 2× RTX 5090 和一个月)。

## 2. 目标、非目标、反目标

### 目标
- 在 2× RTX 5090 上,本地跑通 ≥2 个开源视频生成模型(首选 **Wan2.1 1.3B / Wan2.2** 与 **CogVideoX-5B**;若 CogVideoX 无法在单卡运行则只跑 Wan)
- 完成**两段式物理一致性评测**:
  - **Part A(可测量物理)**:生成物理量可程序化验证的视频(自由落体、抛体、单摆等),从帧序列提取物体轨迹,拟合物理参数(重力加速度 g、摆动周期 T),与真实物理对照打分
  - **Part B(复杂场景)**:生成复杂物理场景(碰撞、流体、支撑、多物体交互),由视觉语言模型(VLM)裁判逐帧判读,输出"物理违反现象清单"(现象类别 × 出现与否 × 描述)
- 产出 benchmark 代码库(生成脚本、检测工具、裁判协议、leaderboard)与一份结构完整的调研+实验报告

### 非目标(本月不做)
- 训练任何模型;视频域微调(远期可能,不在本月)
- 商业 API 模型评测(保持完全本地、零外部 API 依赖)
- 大规模(几十万视频)评测;本月是**中等规模(每模型每 prompt 少量复现)**的研究性基准
- 覆盖视觉质量类指标(VBench 那套)— 除非作为参考指标顺手报告

### 反目标(以下情况视为失败)
- 结果只是"模型 A 比模型 B 好"而没有物理量数值依据(Part A 必须输出可核验的物理数值)
- Part B 的裁判过程不可复现(裁判协议必须写成代码)
- 花大量时间调 API 或处理模型下载失败等不可控因素(预算留给分析与写作)

## 3. 约束

- **硬件**:2× RTX 5090,各 32 GB。已知问题:驱动与 PyTorch 不匹配(nvidia-smi 报 NVML 错误),第 0 周先修环境。若无法修复,回退为 CPU 推理(慢)或更换设备。
- **网络**:HuggingFace/GitHub 可达。优先选许可宽松、权重易下载的模型。避免 gated 模型(如某些 ACE 仓库是 gated 401)。Wan 与 CogVideoX 均为开放许可(apache-2.0)。
- **时间**:一个月(约 4-5 周)。
- **预算**:0 API 费用。Part B 裁判使用 Claude(通过本机 agent 的 Read 工具读图),不需要额外 API 开销;协议写成可插拔后端。

## 4. 产品决策(已与作者确认)

### 4.1 评测对象
- **主测**:Wan2.1 1.3B(Wan2.2 若可用优先)、CogVideoX-5B
- **量级**:每模型每 prompt 生成 N=2-3 个种子(控制随机性);prompt 总数控制在单模型生成视频 ≤100 段(考虑 5090 生成速度)
- **回退**:若 CogVideoX-5B 显存/依赖失败,只跑 Wan;报告如实说明

### 4.2 Part A:可测量物理评测
- **现象清单**(初版,均为"单物体+背景可分离"场景,便于自动检测):
  1. **自由落体**:小球从画面顶部下落,背景纯色
  2. **水平抛体**:小球以水平初速抛出
  3. **单摆**:摆球悬挂摆动
  4. **水平匀速/减速**:小球在平面上滚动减速(摩擦)
- **检测管线**:视频抽帧 → 前景分割(简单背景减除/颜色阈值,备选 SAM)→ 物体质心跟踪 → 轨迹 → 物理量拟合
  - 自由落体:拟合 `y(t) = y0 + v0*t + 0.5*g*t²`,提取 g,与 9.8 m/s² 对照(需像素→米标定;标定物/已知长度入画)
  - 单摆:提取 x(t),拟合正弦,周期 T 与 `T = 2π√(L/g)` 对照
  - 抛体:拟合抛物线轨迹
- **检测器验证(作者已确认)**:正式评测前,用**合成物理动画**验证检测管线——执行者用代码渲染已知物理参数(如 g=9.8、L=1m)的自由落体/单摆动画,检测器必须从中恢复出正确参数(误差在容差内),才通过验证。验证结果写进报告(证明"可核验物理数值"这一宣称成立,而非跟踪伪影)。
- **打分**:每现象输出物理参数量值与相对误差,汇总成 Part A 得分
- **注意**:视频生成模型对物理常数的理解很可能差——这本身就是结果。Part A 的价值在于**客观可核验的数值**,而非高分

### 4.3 Part B:复杂场景 VLM 裁判
- **现象清单**(初版,每类 2-4 个 prompt):
  1. 碰撞与动量(两球相撞、台球)
  2. 流体行为(倒水、水面涟漪)
  3. 支撑与稳定(叠放、桥)
  4. 多物体交互(抛接、多米诺)
  5. 常见违反清单场景(失重漂浮、穿模、支撑失效)
- **裁判协议**:ffmpeg 抽帧(每段均匀 8-12 帧)→ **Claude 作为 VLM 裁判**(通过本机 Read 工具看帧)→ 按结构化量表打分:
  - 每类现象:(a) 是否出现物理违反(0/1/多处)(b) 违反描述(一句话)(c) 置信度
  - 汇总输出:每模型每类现象的违反率 + 平均违反数
- **可复现性**:裁判协议写成代码(帧采样脚本、评分 prompt 模板、输出 schema)。后端可插拔:默认 Claude,可换成 GPT-4o/Gemini(需 API key)重跑验证。报告记录裁判模型与版本。
- **诚实限制(写入报告)**:Claude 裁判只读**静态帧**,不判时间动力学;时间相关物理(周期、加速度)归 Part A。Part B 只判"帧上可见的物理错误"。

### 4.3b Part B 裁判协议的执行细节(执行者决定,已定)
以下为执行者(agent)的决定,非作者逐条确认:

- **执行方式**:每段视频的裁判调用在**独立会话/独立调用**中进行,使用固定模板 prompt + 固定输出 JSON schema;不做跨视频的上下文共享,避免上下文漂移影响打分。
- **盲评**:裁判调用不附带模型身份信息,只给视频 ID 与帧;模型身份在分析阶段才合并。
- **模型版本固定**:裁判模型名称与版本记录在结果元数据中;若月中更换模型,则对所有已判视频重新裁判一次并披露。
- **归档**:每段视频的裁判输入(帧网格)与输出(JSON)全部落盘归档,作为证据产物提交。
- **跨后端重跑**:本月不实际调用付费 API(GPT-4o/Gemini),但代码支持用 `OPENAI_API_KEY`/`GEMINI_API_KEY` 环境变量切换后端,重跑路径已就绪。报告说明此限制。
- **校准集(作者已确认)**:设计少量"答案已知"的控制 prompt(如"一个飘在空中静止不动的人"、"(无支撑)悬空的水杯"),这些场景的违反是确定的。裁判必须正确识别控制集的全部明显违反,否则裁判协议判无效、重做。校准集结果作为 Part B 可信度的证据写进报告。

### 4.4 调研报告
- 结构:引言(为什么物理一致性重要)→ 相关工作(现有基准与方法学对比表)→ 本基准设计(两段式)→ 实验结果(Part A 数值 + Part B 违反清单 + 模型对比)→ 讨论(失败模式、与现有基准的关系、局限)→ 未来工作(可扩展成论文的部分)
- 语言:英文为主(论文底稿),关键章节可附中文摘要
- 定位:报告写成**未来论文的方法学+结果章节的底稿**,不只是实验记录

## 6. 关键风险

| 风险 | 应对 |
|---|---|
| 驱动/CUDA 环境坏 | 第 0 周修;回退 CPU(慢但可行) |
| CogVideoX-5B 单卡跑不动 | 只跑 Wan;或量化;如实报告 |
| Part A 检测器对生成视频失效(伪影、物体形变) | 检测器多策略:颜色/背景减除/SAM;报告失败样本 |
| Part B 裁判争议 | 协议固定+可插拔后端;报告局限;校准集验证(§4.3b) |
| 生成视频物理错误太多导致指标无区分度 | 这是有效结果;报告如实呈现 |
| 时间不够 | 先 Part A(客观)+ 最小 Part B;报告可后续扩展 |
